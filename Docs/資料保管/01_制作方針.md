## 1. ゴール

- Unity で動く TPS（第三人称シューター）ゾンビゲーム用のプレイヤーキャラクターを制作する。
- 完成イメージは参照画像3枚（正面A-Pose / 正面T-Pose / 側面）。
- 主要アニメーションは自作する。Mixamo は参考・仮置き・リターゲット検証用。
- 最終目標：銃を構えたままの8方向ストレイフ移動、戦闘、しゃがみ、ノックバック等の特殊動作まで実装する。
- ポートフォリオとして「どの段階で止めても動くものが見せられる」進め方をする。

## 2. 基本方針

### 2-1 座標系
- Blender の座標系で作成する（Z＝上、キャラクター正面＝−Y、キャラクターの左＝+X）。
- Unity への変換は FBX 出力時に行う。出力設定は初回テスト出力で確定し、02 に記録する。

### 2-2 モデリング姿勢
- モデリングとバインドは画像①の A-Pose（腕を体側から約25°開く）で行う。
- T-Pose は「寸法の基準（画像②）」と「変形チェック用ポーズ」として使う。
- Unity では Avatar 設定の「Enforce T-Pose」で Humanoid 化する。

### 2-3 Unity 側で管理するもの
Blender の IK コンストレイントは FBX に含まれず、Humanoid リターゲットでも失われる。そのため、以下は Unity 側（Animation Rigging パッケージとスクリプト）で管理する。
- 左手を武器に追従させる（Two Bone IK）
- 照準方向への上半身の向け（Multi-Aim：背骨・胸）
- 頭の視線（Multi-Aim または Humanoid LookAt）
- 足の接地補正（Humanoid Foot IK）
- 武器の Grip / Muzzle 位置（武器プレハブ側の空オブジェクト）
- 腕の Twist 補助ボーンの回転（Twist Correction）

Blender の IK ボーンは「アニメーションを作るための操作用」と割り切り、FBX には含めない。

### 2-4 移動とルートモーション
- 基本は「その場アニメーション＋スクリプトで移動」。
- ボタン1回で発動し、その動作自体が移動するもの（回避、ノックバック、ダウン、着地ローリング等）はルートモーションを使う。
- ルートモーションを使うかどうかは、03 の各アニメーション仕様に「移動方式」として個別に記載する。本格制作の前に全項目を確定させる。

### 2-5 移動アニメーションの方向数
- まず4方向（前・後・左・右）で作成し、Blend Tree で斜め移動を補間する。
- 4方向で想定どおりの品質が出たら、8方向（斜め4方向）を追加する。
- 8方向を追加する条件：4方向版で「足の滑り・足の交差・速度のずれ」が許容範囲に収まっていること（§5 のチェックで判定）。

### 2-6 アニメーションの共通化（制作本数を抑える設計）
- 下半身（移動）と上半身（武器の構え）を Animator Layer と Avatar Mask で分離する。移動アニメを武器ごとに作らない。
- 回避（ステップ）と立ったままの被ダメージでは、武器の構えを維持する。地面に伏せる・転がる・吹き飛ぶ全身アクションは、拳銃・ナイフでは「利き手に小型武器を握った共通の腕」で1本ずつ作って共用し、長物などでは腕だけの Mask で抱え込みポーズ（Carry）を重ねる。
- 左利きは、Unity Humanoid の反転で右利きのアニメーションを左右反転して使う。
- 武器切替は「収納（Holster）＋取り出し（Draw）」に分割し、武器の組み合わせの数だけクリップが増えないようにする。
- 武器は重さと形による「持ち方クラス」（拳銃 / ナイフ / 長物 / 肩担ぎ / 弓 / 投擲）で管理する。構え・エイム・取り出し・収納はクラスごとに1本、射撃とリロードは武器ごとに作る（04 §13）。

### 2-7 キャラクター性の演出
- 設定：華奢で、任務経験が浅い女性。
- ゲーム性（入力の反応・キャンセルのタイミング）は損なわない範囲で、緊張感・不慣れさを演技に含める。
  - 例：警戒した見回し、射撃反動がやや大きい、息切れしやすい、ノックバックが大きめ
- 熟練兵のような無駄のない動きより「必死さ・慎重さ」を優先する。

## 5. 制作フェーズ（ロードマップ）

元の工程①〜㉒を、途中でも動くものが残る順番に並べ替えた。

### Phase 0：仕様確定（工程①）← 現在
- 02 と 03 を確定させる。§4 の未決事項を解消する。

### Phase 1：仮キャラで TPS 制御を作る（工程⑱の前倒し）
- Mixamo の仮キャラと仮アニメで、Unity に以下を実装する。
  - 常時ストレイフ移動（D-11）とその場旋回、4方向ストレイフの Blend Tree、しゃがみ、回避（ルートモーション）、ノックバック（ルートモーション）、上半身と下半身の分離、左手 IK、照準、持ち方クラスの切り替え（Animator Override Controller）
  - 弾速のある射撃（銃口から照準点へ弾を飛ばす）、部位ごとの当たり判定、体勢崩しから体術への連携の仮実装
  - 仮のゾンビ（Humanoid の仮モデルと Mixamo のアニメ）で、05 の状態の流れ（感知・追跡・攻撃準備・噛みつき・体勢崩し）を仮実装する
- 目的：Animator の構造と「必要なクリップの一覧」を実機で確定させる。ここで決まった構造に自作アニメを流し込む。

### Phase 2：人体モデル（工程②〜⑥）
- Blender の基準設定 → 画像を配置 → ベースメッシュ → 体型調整 → 頭・手・足の詳細化

### Phase 3：リグとウェイト（工程⑦〜⑩）＋早期 FBX テスト
- Armature 作成 → メッシュに合わせる → ウェイトペイント → 変形チェック
- **この段階で一度 FBX を出力し、Unity で Humanoid Avatar が作れるか、Mixamo アニメで動くかを確認する。**

### Phase 4：顔・髪・服・装備（工程⑪〜⑬）

### Phase 5：補助ボーン・最終チェック・Unity 設定（工程⑭〜⑰）

### Phase 6：自作アニメーション【MVP・4方向】（工程⑲〜⑳）

## 6. 工程ごとの注意ポイント（一緒に気を付ける）

| タイミング | 注意すること |
|---|---|
| ② Blender 基準設定 | 単位はメートル、スケール 1.0。フレームレートは 30fps に固定（アニメの尺を合わせるため）。 |
| ③ 画像配置 | 画像はブーツ込みの身長。**素足の頭頂を 1.600m** に合わせ、ブーツの厚み（約3〜4cm）は足元で吸収する。AI 生成画像は正確な正投影ではないため、数値（02）を優先する。 |
| ④ ベースメッシュ | ミラーモディファイアで左右対称に作る。四角ポリゴン中心。関節（肩・脇・肘・手首・股関節・膝・足首・指）に最低3本のエッジループを入れる。 |
| ④〜⑥ | オブジェクトのスケールと回転は常に適用済み（1.0 / 0°）にしておく。 |
| ⑥ 詳細化の完了時 | **ここでトポロジーを確定させる。** ⑪で Shape Key を作った後に頂点を増減すると、Shape Key が壊れる。 |
| ⑦ Armature | ボーンは片側だけ作り、Symmetrize で反対側を作る。ロールを統一する（肘・膝が同じ軸で曲がるように）。肘と膝はわずかに曲げておく（02 の座標どおり）。 |
| ⑦→⑧ | Armature オブジェクトのトランスフォームも適用済みにする。 |
| ⑧ 早期 FBX テスト | Unity で Humanoid Avatar が緑（正常）になるか確認する。Mixamo の Idle / Walk / Aim を当てて破綻がないか見る。 |
| ⑨ ウェイト | A-Pose でモデリングしているため、**腕を水平より上に上げたときの肩**（エイム・投擲）を重点的に確認する。 |
| ⑪ 顔 Shape Key | ミラーモディファイアを適用してから作る（Shape Key があるとモディファイアを適用できなくなる）。 |
| ⑬ 服・装備 | 服の下に隠れる体のメッシュは削除するか、マスクで非表示にする（貫通防止と軽量化）。ポーチやホルスターなど硬い装備は、1本のボーンに100%のウェイトで固定する。しゃがみ・エイム・投擲の姿勢で、服が体を突き抜けないか確認する。 |
| ⑭ 補助ボーン | IK 操作用のボーンは Deform を OFF にする。Weapon_R / Weapon_L は FBX に残すため Deform を ON にする（ウェイトは0）。 |
| ⑯ FBX | Add Leaf Bones は OFF。Only Deform Bones は ON。アニメーションは Action 単位で出力する。 |
| ⑰ Unity Humanoid | Enforce T-Pose を実行する。筋肉の可動域（Muscles）を確認する。 |
| ⑲ アニメ制作 | 03 に定めた移動速度と1周期のフレーム数を守る（守らないと足が滑る）。ループの最初と最後のフレームを一致させる。 |
| ⑳ Animator | ルートモーションを使うクリップは「Bake Into Pose」の設定を 03 の指定どおりにする。 |
| 常時 | Blender ファイルは連番で保存する（例：_v001, _v002）。作業フォルダを1か所に統一する（OneDrive と C:\ に同名プロジェクトがあるため注意）。 |
