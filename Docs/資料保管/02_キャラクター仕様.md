## 2. 座標系（Blender）

| 軸 | 意味 |
|---|---|
| +Z | 上（床は Z=0、素足の頭頂は Z=1.600） |
| −Y | キャラクターの**前** |
| +Y | キャラクターの後ろ |
| +X | キャラクターの**左**（ボーン名の _L 側） |
| −X | キャラクターの右（ボーン名の _R 側） |

- 原点（ワールドの 0,0,0）は、左右の足の中間の床面とする。
- Blender の正面ビュー（テンキー1）で、キャラクターの顔がこちらを向く。

## 3. 画像の使い分け

| 画像 | 使う目的 | 使わない目的 |
|---|---|---|
| ① 正面・A-Pose | **モデリング姿勢**、顔、胴体のシルエット、腰、脚、全体の体型、腕の角度、**腕の長さ** | ― |
| ② 正面・T-Pose | 服と装備の見た目の確認 | **腕の長さ**（両腕を広げた長さが身長の73%になり、画像①と矛盾するため使わない） |
| ③ 側面 | 胸・ウエスト・骨盤の厚み、背中、頭の前後位置、骨盤の前傾、膝の位置、足の長さ | 腕の前後位置（腕が前に出ているため） |

- 画像はブーツ込みの見た目。体を作るときは、素足の頭頂 1.600 を基準にする。
- ブーツを履いた完成モデルは、靴底の厚み（画像の採寸で約3.2cm）の分だけ体が上がる。Unity では靴底が地面（高さ0）に来る必要があるため、ブーツを作る段階で体・骨格・服の全体を靴底の厚み分だけ持ち上げ、この資料の Z 座標にも同じ量を足した値を「完成時の座標」として記録する。
- Blender 上の参考画像（CH_PlayerF_v001.blend の REF コレクション）は、画像の髪の上端を1.62m、靴底を−0.035m に合わせて配置した。
- 寸法は、画像①・③に高さ5cmごとの目盛りを重ねて採寸した値を基にしている（D-69 案B）。画像は脚が長く腕が短い、ファッションイラスト寄りの比率。
- AI 生成画像は正確な正投影ではないため、正面と側面の間や左右で細かく食い違う。**モデリング中に画像と数値が食い違う場合は、この資料の数値を優先する。**

## 6. 側面の姿勢

- 自然なS字姿勢。極端な反り腰や猫背にはしない。
- 骨盤の前傾は約5°。お尻は後ろへしっかり出る（画像③）。
- 頭の中心は体の中心線より約3cm 前（Y=−0.030）。画像③の頭はさらに前に出ているが、不自然にならない範囲に抑えた。
- 股関節と足首は、前後方向でほぼ一直線上（Y=+0.010）。膝はそれより 2cm 前（Y=−0.010）。

- Head＝ボーンの始点、Tail＝ボーンの終点。親の Tail と子の Head は同じ位置（接続）とする。

- 指を曲げる方向は手のひら側（T-Pose では −Z）。

## 8. Armature の構造

Unity Humanoid の背骨の枠（Hips / Spine / Chest / UpperChest）に合わせて、元仕様の Spine_02 を削除した。Root ボーンも廃止した（下記の注を参照）。

```
Armature（オブジェクト。原点＝床の中心）
└─ Pelvis
   ├─ Spine
   │  └─ Chest
   │     └─ UpperChest
   │        ├─ Neck
   │        │  └─ Head
   │        │     ├─ Jaw
   │        │     ├─ Eye_L
   │        │     └─ Eye_R
   │        ├─ Clavicle_L
   │        │  └─ UpperArm_L
   │        │     ├─ UpperArm_Twist_L      ※補助（Humanoid 外）
   │        │     └─ LowerArm_L
   │        │        ├─ LowerArm_Twist_L   ※補助（Humanoid 外）
   │        │        └─ Hand_L
   │        │           ├─ Thumb_01_L ─ 02 ─ 03
   │        │           ├─ Index_01_L ─ 02 ─ 03
   │        │           ├─ Middle_01_L ─ 02 ─ 03
   │        │           ├─ Ring_01_L ─ 02 ─ 03
   │        │           ├─ Pinky_01_L ─ 02 ─ 03
   │        │           └─ Weapon_L           ※武器・小道具の取り付け位置
   │        └─ Clavicle_R（左と同じ構造。Weapon_R は Hand_R の子）
   ├─ Thigh_L
   │  └─ Calf_L
   │     └─ Foot_L
   │        └─ Toe_L
   └─ Thigh_R（左と同じ構造）
```

**Root ボーンを廃止した理由**
Unity Humanoid はルートモーションを「体の重心の動き」から計算するため、Root ボーンの動きを使わない。Root ボーンがあると「どちらを動かせばよいか」が混乱するので、Armature オブジェクト自体を原点として扱う。ルートモーションが必要なアニメーションでは、Pelvis ごと体全体を移動させる。

### 8-1 補助ボーン（Humanoid 以外）

| ボーン | 親 | 用途 | Deform |
|---|---|---|---|
| UpperArm_Twist_L/R | UpperArm | 上腕のねじれ補正（上腕の中間に配置） | ON |
| LowerArm_Twist_L/R | LowerArm | 前腕のねじれ補正（手首の手前 1/3 に配置） | ON |
| Weapon_R | Hand_R | 右手に持つ武器の取り付け位置と、武器のアニメーション | ON（ウェイト0） |
| Weapon_L | Hand_L | 左手に持ち替えた武器、マガジン、アイテム | ON（ウェイト0） |

- Twist ボーンは Humanoid アニメでは回転しない。Unity 側で Twist Correction（Animation Rigging）を使い、手首の回転から回転量を計算する。
- Weapon_R / Weapon_L は FBX に含めるため Deform を ON にする。アニメーションを取り込む設定（Mask の Transform）で、これらのボーンを有効にする。

### 8-2 Blender 専用の操作ボーン（FBX に含めない）

| ボーン | 用途 |
|---|---|
| Hand_IK_L / Hand_IK_R | 腕の IK ターゲット。武器を持つアニメでは、Hand_IK_L を Weapon_R の子にして左手を武器に追従させる |
| Foot_IK_L / Foot_IK_R | 足の IK ターゲット |
| Knee_Pole_L / Knee_Pole_R | 膝の向き（前 −Y） |
| Elbow_Pole_L / Elbow_Pole_R | 肘の向き（後ろ +Y） |

- すべて Deform を OFF にし、ボーンコレクション「CTRL」にまとめる。

### 8-3 武器プレハブ側で持つもの（キャラクターの Armature に入れない）

| 名前 | 用途 |
|---|---|
| Weapon_Grip | 武器の握り位置（武器モデルの原点） |
| Weapon_Muzzle | 銃口の位置と向き（弾・マズルフラッシュを出す位置） |
| LeftHand_Target | 左手 IK のターゲット（フォアグリップや銃の握り） |
| Light_Mount | ライトを武器に付ける位置（D-64） |

- Blender でアニメーションを作るときは、武器モデルを Weapon_R の子にする。
- 持ち方クラス（04 §13）ごとに、握り位置を確認するための仮の武器モデルを用意する（拳銃、ナイフ、長物、肩担ぎ、弓）。

### 8-4 収納ソケット（Unity 側の空オブジェクト。ボーンは追加しない）

| ソケット | 親ボーン | 収納するもの | 状態 |
|---|---|---|---|
| Socket_Holster_Pistol | Thigh_R | 無限ピストル | 決定 |
| Socket_Sheath_Knife | UpperChest（胸ハーネスの左側） | ナイフ | 決定 |
| Socket_Pouch_Grenade | Pelvis（ベルトの左ポーチ） | 手榴弾 | 決定 |
| Socket_Pouch_Item | Thigh_L（左太もものポーチ） | 回復アイテム | 決定 |
| Socket_Pouch_Mag | Pelvis（ベルトの前側） | 予備マガジン | 決定 |
| Socket_Holster_Back | Pelvis（腰の後ろ） | マグナム／リボルバー | 決定 |
| Socket_Back_1 | UpperChest（背中に斜め掛け） | 戦闘用武器の1枠目（長物・ランチャー・弓） | 決定（角度は【暫定】） |
| Socket_Back_2 | UpperChest（バックパックの横に縦に吊るす） | 戦闘用武器の2枠目 | 決定（位置は【暫定】） |
| Socket_Light_Hand | 利き手と反対の手（手の甲。グローブの上） | ライト（常時装備）。手の甲か武器のどちらかに付ける（D-64） | 決定 |

- 表の左右は右利きの場合。左利きのときは、利き手側と反対側のソケットを入れ替える（Socket_Holster_Pistol は Thigh_L、ナイフの鞘は胸の右側など）。左右それぞれのソケットを用意しておき、スクリプトで使う側を切り替える。
- 武器は全て体に表示する（D-22）。背中に2本を背負った状態で、バックパック・髪・腕と武器が貫通しないかを、⑬の装備制作時に確認する。

### 8-5 命名規則

- 左右は末尾に `_L` / `_R` を付ける（Blender の左右反転機能が認識する形式）。
- 指の名前は `指名_番号_左右` の形式にする（例：`Index_02_L`）。

## 10. 顔

### 10-1 構成
- Head の子に Jaw / Eye_L / Eye_R を置く。
- 口の開閉は **Jaw ボーン**で行い、唇の形は Shape Key で作る（元仕様の Mouth_Open / Mouth_Close は Jaw に統合した）。

### 10-2 Shape Key

| 分類 | 名前 |
|---|---|
| 目 | Blink_L, Blink_R, Blink_Both, Eye_Squint, Eye_Wide |
| 眉（追加） | Brow_Up, Brow_Down, Brow_Inner_Up（悲しみ・恐怖）, Brow_Angry（眉間を寄せる） |
| 口 | Mouth_Smile, Mouth_Frown, Mouth_Wide, Mouth_Grimace（歯を食いしばる：痛み・力み） |

### 10-3 基本表情（Shape Key の組み合わせで作る）
Neutral / Smile / Angry / Sad / Surprised / Fear / Pain / Exert（力み：回避・投擲・起き上がり）

TPS では顔が映る時間が短いため、優先度は「Blink → Pain → Fear → Exert → その他」とする。

## 11. メッシュの方針

- TPS では全身が常に画面に映るため、関節を曲げても破綻しにくいトポロジーにする。
- 重点部位：肩・脇・肘・手首・背骨・腰・股関節・膝・足首。
- 各関節に3本以上のエッジループを入れる。肘・膝の裏側は、曲げたときに潰れないようループの間隔を詰める。
- 想定する動作：ナイフ攻撃、射撃、リロード、回避、ダッシュ、ジャンプ、着地、しゃがみ、ダウン、起き上がり。
- A-Pose でモデリングするため、腕を上げる姿勢（エイム・投擲）での肩の変形を早い段階で確認する。

### 11-1 容量の目安【暫定】

| 項目 | 目安 |
|---|---|
| 全体の三角ポリゴン数 | 3万〜5万（服・装備・髪を含む） |

## 13. FBX 出力設定（D-55：Claude が決定。初回テストで確認する）

### 13-1 Blender 側（File > Export > FBX）

| 項目 | 値 | 理由 |
|---|---|---|
| Limit to：Selected Objects | ON | Armature とキャラクターのメッシュだけを出力する（ライトや参考画像を含めない） |
| Object Types | Armature、Mesh | ― |
| Apply Scalings | FBX Units Scale | Unity でスケールが 1 になる |
| Forward | -Z Forward | Blender（Z 上）から Unity（Y 上）へ軸を変換する設定 |
| Up | Y Up | 同上 |
| Apply Transform | ON | 軸の変換を Armature に焼き込み、Unity で回転 0・スケール 1 にする |
| Armature：Primary / Secondary Bone Axis | Y / X | Blender のボーンの向きのまま出力する |
| Armature：Only Deform Bones | ON | IK 操作用のボーン（02 §8-2）を含めない |
| Armature：Add Leaf Bones | OFF | 末端に余分なボーンを追加しない |
| Bake Animation | モデル用の FBX では OFF。アニメーション用の FBX では ON | モデルとアニメーションを別の FBX で管理する |
| Bake Animation：NLA Strips / All Actions | All Actions を ON（アニメーション用の FBX のみ） | Action 1つが Unity のクリップ1つになる |

### 13-2 Unity 側（FBX を選択 → Inspector）

| タブ | 項目 | 値 |
|---|---|---|
| Model | Scale Factor | 1 |
| Model | Bake Axis Conversion | 初回テストで向きが正しければ OFF のまま。回転がずれる場合は ON を試す |
| Rig | Animation Type | Humanoid |
| Rig | Avatar Definition | モデル用の FBX では Create From This Model。アニメーション用の FBX では、モデル用の FBX の Avatar を指定（Copy From Other Avatar） |
| Rig | Configure | ボーンの割り当て（§9）を確認し、Enforce T-Pose を実行する |
| Animation | Root Transform の Bake Into Pose | 03 §1-4 の移動方式の区分に従う |

### 13-3 初回テストの手順（Phase 3 の早期 FBX テスト）
1. Blender で、キャラクターの正面が −Y を向いていること、Armature とメッシュの回転が 0・スケールが 1（適用済み）であることを確認する。
2. 上の設定で出力し、Unity に読み込む。
3. シーンに置いたとき、次の3点を確認する。
   - キャラクターが Unity の +Z 方向（青い矢印の方向）を向いている。
   - Transform の Rotation が (0, 0, 0)、Scale が (1, 1, 1)。
   - 身長が約1.6（素足）になっている。
4. 向きが逆（背中が +Z を向いている）場合は、Blender でキャラクターを Z 軸で180°回転させて適用し直すのではなく、まず Unity の Bake Axis Conversion を試す。それでも直らない場合に Forward の設定を変える。変えた値は、この表に記録する。
5. Humanoid の Avatar が正常に作られ（Configure でエラーが無い）、Mixamo の Idle と Walk を当てて破綻が無いことを確認する。
